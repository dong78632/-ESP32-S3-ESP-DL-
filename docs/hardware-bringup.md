# 从零采购与硬件联调

目前项目包含源码、构建配置、Wi-Fi/MQTT、自动 Light Sleep 和主机资源
生命周期测试。尚未完成 ESP-IDF/Xtensa 交叉编译及实物验证。主机的
1000 次循环测试验证模拟环境中的释放顺序，不能替代真实摄像头、无线电
及低功耗测试。

当前 ESP-DL 模型检测人脸。若毕业设计要求识别背影、遮脸或画面中只出现
身体，需要接入真正的人体/行人模型，并重新核对 SDK、预处理和性能。

## 采购清单

优先选择有厂家原理图、配套摄像头插座、USB 下载接口和已焊排针的
ESP32-S3 板卡，例如 Freenove ESP32-S3 WROOM 摄像头套装。采购时向
商家确认实际模组型号、Flash/PSRAM 容量以及配套摄像头型号；建议
8 MB PSRAM、至少 8 MB Flash，并选择配套 OV2640。N8R8/N16R8 是
可考虑的内存规格，不能用外观或商品标题代替实物型号核对。

| 物品 | 数量 | 要求 |
| --- | --- | --- |
| ESP32-S3 开发板与 OV2640 | 1 套 | 配套插座、8 MB PSRAM、至少 8 MB Flash、已焊排针 |
| HC-SR501 PIR 模块 | 1 个 | 确认供电规格和兼容 3.3 V 的 OUT 电平 |
| 有源蜂鸣器模块 | 1 个 | 带驱动电路，控制端兼容 3.3 V，优先高电平触发 |
| 普通 LED 与 330 Ω 电阻 | 各数个 | 独立报警指示灯，电阻按实际 LED 校核 |
| 面包板与杜邦线 | 1 套 | 公对公、公对母 |
| USB 数据线 | 1 根 | 接口匹配并支持数据传输 |
| USB 电源 | 1 个 | 稳定的 5 V / 2 A 电源 |
| 数字万用表 | 1 个 | 检查电源、电平与共地 |

含基础工具先预留约 250–450 元；此范围为预算估算，未实时询价。
初期无需屏幕、电池、SD 卡、外壳或定制 PCB。

厂家资料：[Freenove ESP32-S3 WROOM Board](https://github.com/Freenove/Freenove_ESP32_S3_WROOM_Board)。

## 到货前的电脑准备

1. 在将通过 USB 连接开发板的电脑上安装 ESP-IDF v5.0.6，以匹配本项目
   的 ESP-DL v2.0。安装结束后先确认 `idf.py --version`。
2. 安装 MQTTX，准备连接 Broker 并订阅报警主题。
3. 准备 2.4 GHz Wi-Fi，首次联调可使用 WPA2 手机热点。
4. 获取完整工程，在 ESP-IDF 开发终端中构建：

```sh
git clone https://github.com/dong78632/-ESP32-S3-ESP-DL-.git esp32s3-edge-security
cd esp32s3-edge-security
idf.py set-target esp32s3
idf.py menuconfig
idf.py build
```

首次构建需要网络下载摄像头和 ESP-DL 组件。Flash 大小及 Quad/Octal
PSRAM 配置必须与实物一致。实际开发板确定后还需修改摄像头与外设引脚，
并填写 Wi-Fi 占位符；完成构建不表示当前暂定引脚适用于购买的板卡。

## 分阶段联调

| 顺序 | 操作 | 通过标准 |
| --- | --- | --- |
| 1 | 只接开发板与 USB，烧录基础示例 | 串口可识别、烧录成功、日志稳定 |
| 2 | 检查 Flash 和 PSRAM | 容量与实物一致、PSRAM 初始化成功 |
| 3 | 运行厂家摄像头示例 | 画面清晰、方向正确 |
| 4 | 适配引脚并运行本工程 | 合法的 320×240 RGB565 帧和推理日志 |
| 5 | 单独测试 PIR、LED、蜂鸣器 | 电平正确，报警结束后输出关闭 |
| 6 | 测试完整闭环 | PIR → 视觉确认 → 声光报警 → MQTT JSON |
| 7 | 启用省电并长期运行 | 待机电流下降、连接稳定、连续触发不异常 |

推荐先用关闭自动睡眠的调试固件建立基础闭环，再开启省电对比。
当前工程还没有独立的睡眠调试开关；需要在板卡适配时增加。
仅关闭 `CONFIG_PM_ENABLE` 或 Tickless Idle 会触发当前编译期检查，
不能直接作为关闭睡眠的方法。

摄像头初始化发生在启动检查和每次视觉触发时。当前按需初始化会增加
响应时间，可能影响首帧曝光；需要实测。完整固件启动会先等待 Wi-Fi
获得 IP，所以首次运行前须填写有效的 SSID/密码。

## 接线原则

- `main/main.cpp` 中的摄像头和外设 GPIO 均为暂定值，需要对照实际
  板卡原理图修改。Freenove 板卡的摄像头映射与当前暂定映射不同。
- 摄像头优先使用厂家配套插座，并在断电时插拔排线。
- 所有模块共地。ESP32 GPIO 不能接入 5 V，模块供电端与逻辑信号端
  应分别核对规格。
- 裸蜂鸣器不能直接由 GPIO 带载，应使用驱动电路或带驱动的模块。
  LED 串联限流电阻。
- 板载 LED、SD 卡、USB、PSRAM 可能占用 GPIO；不要仅凭排针标号
  判断引脚可用。

## 论文实验记录

从首次联调开始保存固件版本、板卡型号、接线、日志和测试条件。
至少记录检测距离、光照、误报/漏报、推理耗时、PIR 到报警的总延迟、
MQTT 接收情况，以及省电前后的整板平均电流。

待基础闭环稳定后，再加入连续触发、Wi-Fi 断线恢复、摄像头反复初始化、
内存剩余量与最大空闲块、长时间运行和温升测试。最终按稳定的原型设计
固定支架与外壳。
